# 委派与上下文交接规则

本文件是写作委派条件的唯一依据。先完成综合单元计划，再决定如何执行；skill 加载和子代理调用是两件事。以下规则针对单元起草，独立审核器仍只在明确需要时调用。

## 1. 顺序判定

以 synthesis_plan.md 中实际需要起草的综合单元数 U 为依据；续写已有指南时，只计本次需要新写或实质改写的单元。

1. 用户明确指定就地完成或使用子代理：采用用户指定模式。用户要求就地完成时，主编排器逐单元起草。
2. 未指定模式且 U ≤ 4：主编排器就地起草，采用 study-note-unit-writer 的正文片段与交接 JSON 契约。
3. 未指定模式且 U > 4：主编排器委派综合单元写作器，按教学顺序一次交付一个单元，默认同时只有一个写作子代理。
4. 需要委派但环境没有可用的子代理工具，或调用被权限拒绝：记录实际原因，转为 local-fallback，逐单元就地完成。普通执行错误先定位并修复；不能把任务复杂、遗漏任务包或未注册专用 agent 当作工具不可用。

所有就地模式均先读取 study-note-unit-writer/SKILL.md 及其 references/unit-writing.md。单元按教学问题或连续模型分组，先定内容边界再计算 U；不能为了触发或规避委派拆分、合并单元。源文件数与页数帮助规划内容，不单独决定模式：一个长 PDF 可以包含很多单元，多份短资料也可以合成一个单元。阈值 4 是当前工作约定，尚非经实测证明的最佳值。

在 synthesis_plan.md 记录 U、execution_mode（local / delegated / local-fallback）、用户覆盖指令（若有）、选择原因与已完成单元。写作途中不因模型偏好临时换模式。范围改变时先更新计划，再按本规则重新判定；已完成单元保留。仅做原单元的小修不会增加 U。

| 未指定模式时的计划 | 执行结果 |
| --- | --- |
| 一个 PDF、2 个单元 | 就地写 |
| 一个 PDF、12 个单元 | 委派写 |
| 三份短资料、合成 2 个单元 | 就地写 |
| 4 个单元 / 5 个单元 | 分别就地 / 委派 |

## 2. Claude Code 调用

委派分支通过环境实际提供的子代理工具调用写作器，当前 Claude Code 使用 Agent，旧版本可能显示 Task。若会话中注册了 study-note-unit-writer 子代理，使用它；否则使用可写文件的 general-purpose 子代理，在任务包中提供写作 skill 与参考文件的绝对路径，并要求先读取。仓库的 .claude/agents/study-note-unit-writer.md 是原生注册定义；agents/openai.yaml 仅为 Codex 元数据。

加载或输入 /study-note-unit-writer 本身不能作为“已委派”的证据。记录实际调用返回的 agent ID。相邻单元优先恢复同一个写作器，使用本会话提供的恢复能力；新调用若不携带恢复标识，按新上下文处理，重新提供任务包。不能假定新子代理继承主对话或此前加载的 skill。

本单元两份文件完成并经主编排器接收后，才发送下一单元。部分结果或中断不算完成；继续同一任务，完成前保持 drafting 状态。写作器只编辑分配给自己的正文与交接文件，文件路径不与总稿、计划、其他单元重叠；整本统稿与编译由主编排器负责。

需要独立审核时，另行委派可读取材料的子代理加载 coverage-audit-note-reviewer skill；写作器的自查不充当独立审核。用户指定就地完成或环境无法委派时，由主编排器自审并说明没有独立复核。

## 3. 文件维持连续性

主编排器保留 source_inventory.md、synthesis_plan.md、continuity.md 和全部单元文件。continuity.md 只记录可复用的定义、记号、结果键、正文标签及所属单元，不复制整段正文。

每个任务包包含本单元证据、必留结果、已建立的相关定义和记号、前文结果与标签，以及本单元负责新建的定义。附上明确的正文与交接输出路径。写作器将新增或修订的连续性条目放入 handoff 的 continuity_updates；主编排器核对并更新 continuity.md 后再继续。

父会话接收文件路径、覆盖 ID、未决问题与必要的连续性变动，不要求子代理把全文再贴回对话。主编排器最终仍逐单元读取真实正文完成合并与语义去重；文件与标签保证可追踪，不要求所有正文一直驻留在同一上下文中。

## 4. 完成条件

就地、委派和降级模式都交付相同的正文片段、交接记录、全书公式筛选与覆盖对应表；均保留最终编译和结构/PDF 审核步骤。独立审核器可省略不等于主编排器自审可省略。用户明确暂缓测试或编译时，记录待执行项目并交付未验证草稿，不能声称通过验收。

机制依据：[Claude Code 子代理](https://code.claude.com/docs/en/sub-agents)与[Skills](https://code.claude.com/docs/en/skills)。模式规则是本项目约定，不是 Claude Code 自动保证的强制门禁。
