# 审核方法

先展开 TeX 的 input/include，读取 build 中的实际正文。对照用户范围、可用来源和参考稿；只有旧笔记或转录时，不认证原课件覆盖。

## 内容审核先于脚本

1. **知识点与定义：**名称是否准确、边界是否清楚、定义是否紧接入口且完整；模型参数和运算步骤是否被误升为独立点。每个独立概念、定理、结果和题型应有星级；封面图例和星号总数不能代替检查。
2. **重要性：**教师/考试证据优先，推断星级标为暂定。读者能否辨认核心与背景；是否把导读、分析顺序、模型分工和批次总结加星混入知识内容。无须按配额分星。
3. **冗余：**相邻定义、表格、图注、推导和点末文字一起读。指出具体重复语义并合并，删除进入下一点的铺垫和转场。定义可以直接并列，不要求补串联段；也不强制改成“结论先行”的答题清单。
4. **必要解释：**删除衔接后，概念的关键特征、机制、条件和推理是否仍完整；文字减少不能抵消定义含糊或步骤跳跃。
5. **数学：**从设定复算关键链条，检查新符号、条件概率、积分区间、链式法则、约束和边界。尤其核对必要/充分、局部/全局、候选/实现。不能把某点导数为零写成函数不随变量变化。
6. **题目：**逐小问核对题面条件、代入、中间结果和答案；确认决定答案的可行性、最优性或边界判断已实际做出。不能用“检查边界”取代计算。
7. **覆盖：**每个实质来源项有实际正文位置或合理省略，删掉的是重复表达而非独立知识。第二证明若有独立含义或考试要求，不能机械去重。

## 框与 PDF

一个推导/例题是否完整集中在一个框；是否残留设定框—推导框—结果框的连续碎片。普通辅助公式允许无框，不能仅按展示数学是否入框审核。

按 style-contract.md 核对细蓝边、暖白底、小号文字、框内题头、无独立标题栏；原稿的逻辑串联框不能作为生成串联段的理由。查看概念、数学、例题和跨页框的实际渲染，检查文字可读、字体嵌入、链接与引用稳定。

先逐点完成以上内容审核，再读当前输出的编译与校验报告。自动通过仅表示所列结构/技术项通过。页数、字数、星标数和框数只能提示问题，不能作为内容质量的通过标准。

## 输出

仅列具体位置、问题、来源依据和修正建议，给出“通过 / 有说明地通过 / 需修改”。明确区分内容审核与技术结果，附真实未验证项。自审如实称自审。新工程无逐批 JSON 不构成缺陷；公式速查按需在全部正文后集中一次。
